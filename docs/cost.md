# 費用の守り方

本番は、クレジット適用前の総額で合計 ¥2,000 を上限にしています。止める仕組み（上限）と、そもそも使う額を減らす仕組み（くふう）の両方で守ります。

## 上限

外側から順に、次の段で止めます。

| 段 | 止まる額 | しくみ |
|---|---|---|
| Cloud Billing の予算 | ¥2,000 | 2026/11/1 から期限なし。10・20・30・50・80・100% でメールと Pub/Sub に通知する |
| キルスイッチ | 実費 ¥1,900 | 予算通知（Pub/Sub）を受けた Cloud Run 関数が、プロジェクトの課金を自動で外す（`infra/budget-guard`、`KILL_AT_JPY`） |
| アプリ内メーター | 推定 ¥1,800 | API サーバーが、トークン数・Google 検索グラウンディングの検索回数・SafeSearch の枚数から推定額を Firestore に積算し、生成 API を止める（`CAP_JPY`） |
| アカウントごとの上限 | ゲスト ¥50、ログイン ¥300 | 新しく生成した分の推定額を、アカウントごとに累計で積算する（`USER_CAP_GUEST_JPY`・`USER_CAP_MEMBER_JPY`）。ログインは Google、または確認済みのメールアドレス。上限に達しても、キャッシュ済みの内容は見られる |
| AI 動画 | 合計2本 | トランザクションで数え、開始に失敗したら枠を戻す（`VIDEO_LIMIT`） |

- 上限の判定は「使用済み＋実行中の生成の予約額＋今回」で行うので、同時に大量のリクエストを送ってもすり抜けられません。
- Google 検索グラウンディングは 1,000 件あたり $14 ですが、毎月 5,000 件までは無料なので、メーターには無料枠を超えた分だけを積みます（月ごとの件数は Firestore の `meta/grounding`）。
- 匿名アカウントはいくらでも作れるため、`APPCHECK_ENFORCE=1` のときは、App Check で確かめられないゲスト（iOS / Android のアプリなど）の新しい生成を、全員で共有する1日の上限（`UNATTESTED_POOL_JPY`、既定 ¥150）の範囲でだけ受け付けます。新規登録も IP ごとに1時間100件までです。

単価は `server/src/config.ts` の `PRICES`、円換算は `JPY_PER_USD` です。

## 使う額を減らすくふう

- **共有キャッシュ**: 同じモノ・同じ問いの結果は Firestore に保存し、全ユーザーで使い回します。2回目からは無料ですぐに表示します（段階ごとに保存）。
- **段階の言い換え**: 別の段階の解説や深掘りがすでにあるモノは、検索せずに、その文章を読む人の年代に合わせて言い換えて作ります。費用は数十分の一で、事実は足さず、問いの題もそのままです。
- **2段階の解説**: 前半は検索なしの軽いモデルで書き、検索を使うのは後半の1回だけです。
- **必要なときだけ作る**: 図解・AI 動画・クイズは、開いたときにだけ作ります。
- **事前生成**: よく撮られるモノ（サンプル写真に写っているモノなど）は `infra/prewarm.mjs` で先に作っておきます。
